# Session Transcript: merge-typetracer

## Session Overview
Planned and implemented merging the `typetracer` branch into `main`: replacing the yaml/example-parsing test pipeline with typetracer-based tracing, restoring feature parity, and getting the full test suite and `devtools::check()` clean.

## Design Decisions Made

### Decision 1: Drop the yaml pipeline entirely, no compatibility shim
**Chosen:** Fully remove `autotest_yaml()`/`autotest_single_yaml()`/`parse_yaml_template()` and their exclusively-private helpers.
**Rationale:** The pivot to typetracer was already the intended design (issue #76); a shim would maintain two parallel testing pipelines indefinitely.
**Tradeoffs:** Breaking change to the public API surface (`autotest_yaml` removed).
**Proposed by:** joint

### Decision 2: Restrict mutation testing to example-sourced traces
**Chosen:** Traces tagged by typetracer as originating from a package's own test suite feed parameter-type inference only; mutation/fuzz testing runs only against example-sourced traces.
**Rationale:** Resolves the original issue's concern that test-suite calls designed to trigger errors were producing spurious autotest failures.
**Tradeoffs:** None significant — typetracer's CRAN release already exposes the needed `trace_source` field.
**Proposed by:** joint

### Decision 3: Fix underlying performance/correctness bugs discovered mid-implementation, rather than work around them
**Chosen:** When validation runs surfaced a runaway-memory hang, its root causes were traced to (a) typetracer reinstalling a traced package from scratch on every call, and (b) an integer-range test probing `.Machine$integer.max` directly for parameters that control allocation size. Both were fixed at the source (a session-scoped install cache in typetracer, a much smaller probe ceiling in autotest) rather than papering over them in test code.
**Rationale:** The alternative (isolating each call in its own subprocess, or avoiding the trigger) would leave a real usability/safety issue for any consumer.
**Tradeoffs:** Widened scope beyond the original trace_source work; explicitly confirmed before proceeding given the affected code is used broadly.
**Proposed by:** joint

## Tradeoffs Considered
- Time-limit-based guard vs. capping the probed integer value directly for the allocation-risk fix: value-capping was chosen, since R's interrupt checks may not reliably preempt a tight C-level allocation loop.

## Open Questions
- The typetracer-side fixes (install caching, scoped to named/installed packages) were made and verified but deliberately left uncommitted in the sibling repository, per explicit instruction.
