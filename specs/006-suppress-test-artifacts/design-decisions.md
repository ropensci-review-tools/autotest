# Design Decisions: suppress-test-artifacts

## Summary
Suppressed the plot/PDF artifacts and progress-bar ANSI noise that `autotest_package()`
leaves behind when its examples/mutation tests trigger real graphics calls, so that
`make knitr` (root and vignettes) renders cleanly with no leftover files.

## New Design Decisions

### Decision 1: Root-cause fix via a shared null-device helper, not per-document options
**Chosen:** A single internal helper, `with_null_device()`, opens a discarding
`grDevices::pdf(nullfile())` device around any expression and restores whatever device
was already active afterward (device stack is LIFO). Applied at every place arbitrary
package/example code actually executes.
**Rationale:** A per-`.Rmd`-chunk `fig.show = "hide"` fix would only patch the symptom in
each document and would not address the general `Rplots.pdf` residue reported when
testing arbitrary real-world packages.
**Tradeoffs:** Requires finding every execution site rather than one central switch.

### Decision 2: The actual root cause was in the `typetracer` dependency, not this package
**Chosen:** Wrapped the `do.call(typetracer::trace_package, args)` call site in
`R/typetrace-package.R` with `with_null_device()`, rather than patching `typetracer`
itself.
**Rationale:** An implementation-time audit found `typetracer::trace_package()` runs every
documented example in-process via `eval(parse(text = ex))`; its own plot-suppression
attempt (`options(device = NULL)`) only prevents a *new* device from auto-opening and has
no effect once a device is already active (e.g. knitr's per-chunk recording device, or —
discovered during verification — any environment with no default device at all, where
`plot()` otherwise errors outright). Since R's device stack is respected regardless of
which package opens/closes devices, wrapping the call site from this package's own code
was sufficient without touching the external dependency.
**Tradeoffs:** Couples correctness to `typetracer`'s current in-process execution model;
noted as an open item if that internal implementation changes.

### Decision 3: `progress = "bar"` auto-falls-back under knitr
**Chosen:** `autotest_package()` now downgrades `progress = "bar"` to `"none"` when
`isTRUE(getOption("knitr.in.progress"))`.
**Rationale:** `cli`'s progress bar relies on file-descriptor-level tty detection, which
can still read as a real terminal inside a knitr chunk even though knitr has redirected
R-level output, leaking literal ANSI clear-line sequences into rendered documents.
Empirically confirmed `knitr.in.progress` is reliably `TRUE` during this project's
`rmarkdown::render`-based knit targets.
**Relates to:** [[004-fix-progress-reporting]], which introduced the `progress` parameter
and its `cli`-based `"bar"` mode this decision now scopes.

## Integration with Prior Work
Builds directly on stage [[004-fix-progress-reporting]]'s `progress` parameter, adding a
context-aware fallback rather than changing its default behavior. Independent of stages
001/002/003/005's tracing/parsing fixes, though it wraps the same
`autotest_trace_package()` call path stage 001 introduced when merging `typetracer`.

## Issues Resolved
- Untracked `README-*.png` files and literal `[K`/ANSI noise generated by `make knitr`:
  resolved and verified via a full clean re-render (zero new artifacts, no escape-code
  noise, unchanged substantive test-result content).
- General `Rplots.pdf` residue when autotesting arbitrary packages: resolved at the same
  root cause.
- Vignette parity: removed the same copy-pasted dead `fig.path` option from both
  `vignettes/*.Rmd` files.

## Deferred Items
- Full end-to-end verification of `vignettes/autotest.Rmd`'s knit was blocked by an
  unrelated, pre-existing environment limitation (`DT::datatable()` via `webshot`/PhantomJS
  failing headless) before reaching its own `autotest_package(test = TRUE)` chunks;
  verified only up to that point, via the identical code path already confirmed end-to-end
  through the root README.

## Process Notes
- Verification surfaced a real bug in the first implementation attempt
  (`grDevices::nullfile` does not exist — `nullfile()` is a base-R function) and a second,
  substantive finding: the initial fix to `R/typetrace-package.R` was necessary because
  this sandbox has no default graphics device at all, so package examples with plotting
  calls were previously aborting mid-execution and silently truncating traces — a more
  severe manifestation of the bug than initially scoped.
- That discovery exposed a latent bug in an existing test (`test-statspkg.R`'s "autotest
  rnorm" case used `nrow(x) `, which silently evaluates to `logical(0)` rather than failing
  when `autotest_package()` legitimately returns `NULL`); fixed by switching to `NROW()`.
- Full `tests/testthat` suite (65 assertions) confirmed passing with every change applied
  together, after an initial bisection process to isolate the `typetracer`-wrapping fix
  from the additional direct `do.call(x$fn, ...)` sites found during the audit.
